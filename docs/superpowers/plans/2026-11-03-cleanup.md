# Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A real Cleanup screen: measure what could be cleaned in a few well-known, safe places, let the owner review it, and move the chosen items to the Trash (never a permanent delete), then show what was really freed.

**Architecture:** Domain gets cleanup types and ports (`CleanupScanning`, `CleanupMoving`). Data implements them: a measurer for fixed folders under the home folder and a mover that sends top-level entries to the Trash behind the protected-paths guard. Presentation replaces the sample `CleanupViewState`/view with a real state and a review sheet; the App target wires it; Home's suggested action comes from the real estimate. Same layers, rules and review process as the earlier plans (`docs/superpowers/plans/2026-10-29-scanner-engine.md`, `2026-11-02-startup-items.md`).

**Tech Stack:** Swift 6, Foundation (`FileManager`, `URLResourceValues`), Swift Testing.

**Spec:** `docs/superpowers/specs/2026-10-29-mainternance-design.md` (Cleanup) plus the decisions below (the owner asked for the rest of the app to be built at the builder's discretion).

## Decisions (builder's calls)

- Categories, all under the owner's home folder, fixed paths only: **Caches** (`~/Library/Caches`, each direct child), **Logs** (`~/Library/Logs`, each direct child), **Old installers** (`~/Downloads`, direct children that are files ending `.dmg`, `.pkg` or `.iso`, last modified more than 30 days ago), **Developer build caches** (`~/Library/Developer/Xcode/DerivedData`, each direct child; the category simply does not appear when the folder is absent). Nothing else: no Trash emptying (permanent), no system folders, no `/private/var`, no browser profiles, no documents.
- Unit of cleaning is a direct child ("entry") of those roots. The owner reviews a category's entries (name, size, kind) and can untick single entries in the review sheet; categories are on by default except none are cleaned without the review step and an explicit confirm.
- The action is `FileManager.trashItem` per entry (a move to the Trash, reversible by the owner with Finder's Put Back). The app NEVER calls `removeItem`. If trashing an entry fails (in use, permission), that entry is reported as "not moved: reason" and the rest continue.
- Sizes are allocated bytes (`totalFileAllocatedSize`), computed without following symlinks and without crossing volumes; a symlink entry counts as the link itself. Sizes are labelled "about". "Freed" is only claimed after the move succeeded, and the screen says that space returns only when the Trash is emptied by the owner.
- Safety guards: every entry path must be a direct child of its category root (checked after resolving the parent), must not be protected (`ProtectedPaths.isProtected`), must still exist and be unchanged in kind since measuring (a directory that became a symlink, or a file that became a directory, is refused with "changed since measured").
- Caches of running apps can be in use; the screen advises quitting apps first and reports any entry that could not be moved.
- Home: the suggested action ("Free about N GB") comes from the last real measurement (nil/absent until the first measurement exists); it is refreshed at most every 10 minutes and whenever Cleanup measures.

## Global Constraints

- Layer rules: Domain imports only Foundation; Presentation never imports Data; only the App target wires Data; no file access or decision rules in views.
- No permanent deletion anywhere (`removeItem`, `unlink`, `rm` forbidden; the only exemption in the repo is `QuarantineRemoval`). Trash moves go through a closure injected into the Data type so tests NEVER touch the real Trash or the real `~/Library`.
- Paths and names from disk are untrusted: shown with control and bidi characters stripped; never executed; never used to build shell commands (no shell).
- Unknown is nil, never faked; honest copy (no "safe", no "boost").
- `scripts/lint.sh` exit 0, `scripts/check-boundaries.sh`, `scripts/test.sh` green before every commit; commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; every commit builds. Float tolerances in tests.

## Review Focus

- A symlink entry pointing into `/System` or the home folder must be trashed as a link at most, never followed for size or for moving; a category root that is itself a symlink is refused. Pinned in Task 1.
- An entry swapped between measuring and moving (file to directory, directory to symlink, deleted) must not be moved blindly. Pinned in Task 1.
- Huge or deeply nested trees and unreadable subfolders: measuring must be cancellable, must not hang, and an unreadable subfolder makes the entry's size marked "at least". Pinned in Task 1.
- Entry names with odd characters (spaces, newline, leading `-`, RTL override) display safely and move correctly. Pinned in Tasks 1 and 2.
- Trash failure for one entry must not abort the rest nor claim it was freed. Pinned in Tasks 1 and 2.
- Two overlapping measurements (user taps measure twice) must not show an older result over a newer one. Pinned in Task 2.

### Task 1: Domain and Data: measure and move

**Files:** the Domain and Data files above; Test: `Tests/DomainTests/CleanupTypesTests.swift`, `Tests/DataTests/CleanupMeasurerTests.swift`, `CleanupMoverTests.swift`.

**Interfaces (Produces):**
- `public enum CleanupKind: String, Sendable, CaseIterable { case caches, logs, installers, developer }`
- `public struct CleanupEntry: Sendable, Equatable, Identifiable { public let id: String /* absolute path */; public let name: String; public let bytes: Int64; public let isLowerBound: Bool; public let isDirectory: Bool; public let modified: Date? }`
- `public struct CleanupCategory: Sendable, Equatable, Identifiable { public let kind: CleanupKind; public var entries: [CleanupEntry]; public var id: String; public var bytes: Int64; public var isLowerBound: Bool }`
- `public struct CleanupMeasurement: Sendable, Equatable { public let categories: [CleanupCategory]; public let measuredAt: Date; public var totalBytes: Int64 }`
- `public struct CleanupOutcome: Sendable, Equatable { public let moved: [CleanupEntry]; public let failed: [(entry: CleanupEntry, reason: String)] ; public var movedBytes: Int64 }` (make it `Equatable` through a small struct for failures).
- `public protocol CleanupScanning: Sendable { func measure() async -> CleanupMeasurement }`; `public protocol CleanupMoving: Sendable { func moveToTrash(_ entries: [CleanupEntry]) async -> CleanupOutcome }`.
- Data: `public struct CleanupServices: Sendable { public let scanner: any CleanupScanning; public let mover: any CleanupMoving; public init(home: URL = homeDirectoryForCurrentUser, now: @escaping @Sendable () -> Date = Date.init, trash: @escaping @Sendable (URL) throws -> Void = CleanupMover.moveToTrash) }`.

- [ ] **Step 1: Write the failing tests** for each Review Focus line plus: measuring a temp "home" with caches/logs/installers/DerivedData fixtures returns the right categories, entries sorted by size descending, sizes within tolerance of the written bytes (allocated size is block-rounded, so assert `>= written` and `< written + 1 MiB`); installers younger than 30 days, wrong extensions, directories named `x.dmg` and files outside direct children are excluded; the developer category is absent when the folder is absent; the mover trashes through the injected closure (the closure moves the item into a temp "Trash" folder) and returns moved and failed lists; a protected path or non-child path is refused without calling the closure; an entry whose kind changed or which vanished is refused with a readable reason; one failure does not stop the others; cancellation of `measure()` returns promptly.
- [ ] **Step 2: Run** `scripts/test.sh`; expect failures.
- [ ] **Step 3: Implement** the types. Measurer: `FileManager.contentsOfDirectory` for roots (no symlink following; a symlinked root is refused and reported as an unreadable/absent category), a manual enumerator with `.skipsHiddenFiles` OFF (hidden files count), summing `totalFileAllocatedSize ?? fileAllocatedSize`, `isLowerBound` when any subfolder cannot be read, checking `Task.isCancelled`. Mover: re-stat each entry (lstat, no follow) and compare kind with the measured `isDirectory`; parent check by resolving the parent directory and comparing with the root; `ProtectedPaths.isProtected`; default trash closure is `FileManager.default.trashItem(at:resultingItemURL:)`.
- [ ] **Step 4: Run** tests, lint, boundaries; green; `pgrep -f mainternance-runner-` empty; confirm no test touched the real Trash or `~/Library`.
